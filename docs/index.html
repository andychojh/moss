처음 한 번, 네 단계.

스킬 설치 후 초기 설정을 요청하면 됩니다. 필요한 것은 Python 3.10 이상, Obsidian, 그리고 새 볼트 폴더입니다.

04
지금 필요한 일
프로젝트의 실제 작업 폴더를 Codex가 알 수 있게 함께 열어주세요. 같은 폴더를 여러 프로젝트가 쓰면 프로젝트 키로 구분합니다.
복사해서 Codex에 전달
도구가 처리하는 것
읽기 쉬운 파일명, 동일 내용 중복 방지, 수정 이력, 프로젝트별 조회 표.
Codex가 판단하는 것
어떤 기억이 관련 있는지, 무엇이 새 교훈인지, 어느 프로젝트와 연결할 근거가 있는지.
따로 확인할 것
과거 사실의 최신성, 중요한 결론의 검토, 기기 간 동기화와 외부 공개 여부.
매번 “기록해줘”라고 말해야 하나요?
지침 연결을 선택하면 Codex는 중요한 시작·완료 시점에 Moss를 사용하도록 안내받습니다. 다만 호출이 항상 보장되지는 않습니다. 오래 열린 채팅이나 누락이 의심되는 때는 “$moss를 적용해줘”라고 명시하세요. 모든 대화를 실시간으로 기록하는 기능은 아닙니다.
새 기록이 생겼는데 그래프에는 안 보여요.
기본 그래프에서 작업 로그를 숨기기 때문입니다. Home → 분야 → 프로젝트의 표에서 확인하세요. 그래프 검색을 특정 Records 폴더로 바꾸면 로그도 볼 수 있습니다. 이 페이지의 ‘작업 로그도 보기’는 그 차이를 설명하는 예시입니다.
doctor가 통과하면 내용까지 믿어도 되나요?
doctor는 볼트 구조, 프로젝트 연결 정보, 수정본 표시, Canvas 대상, 지침 연결 등을 검사합니다. 내용의 사실 여부, 모든 링크, Obsidian의 실제 화면까지 확인하지는 않습니다. 중요한 판단은 원본과 근거일을 다시 확인하세요.
다른 컴퓨터에서도 쓰려면 어떻게 하나요?
스킬과 볼트를 옮긴 뒤 새 기기의 설정 파일로 경로를 연결하고, 프로젝트 원본 폴더를 맞춘 후 doctor를 실행합니다. Moss가 클라우드 동기화를 제공하지는 않습니다. 동기화된 서로 다른 복사본에 동시에 쓰는 작업은 별도로 조정해야 합니다.
개인 기록이 패키지에 들어 있나요?
배포용 템플릿은 프로젝트와 기록이 없는 상태입니다. 이 안내에 나오는 상품 코드, 프로젝트 이름과 연결은 설명을 위한 가상 예시이며 설치 때 볼트에 추가되지 않습니다. 이 HTML도 로컬 파일을 읽거나 쓰지 않습니다.
